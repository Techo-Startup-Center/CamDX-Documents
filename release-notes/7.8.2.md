# CamDX 7.8.2 Release Notes

This note describes what CamDX 7.8.2 is, what it supports, and what remains outside its scope. It is not an announcement of whole-estate production migration, and it does not authorize members to begin upgrading an existing Security Server.

## 1. Upstream basis

X-Road 7.8.2.

## 2. Supported CamDX packages and platforms

| Track | Package version | Status |
|---|---|---|
| Ubuntu 22.04 Jammy | `7.8.2-1.ubuntu22.04` | Supported |
| Ubuntu 24.04 Noble | `7.8.2-1.ubuntu24.04` | Supported |
| RHEL 9 | `7.8.2-2.el9` | Supported |

Ubuntu Jammy and Noble are maintained as separate, explicitly distinct package tracks, alongside a separate RHEL 9 track; there is no single ambiguous "Ubuntu" track.

## 3. Container artifact

CamDX publishes a container Security Server image:

- Repository: `ghcr.io/techo-startup-center/camdx/security-server`
- Tags: `7.8.2`, `noble-7.8.2` (both resolve to the same image)
- Immutable digest: `sha256:95fa519adf660cf6e61a037ba9250dfdb1467ec06d6a292dbfccc09db7d71c0b`
- Platform: `linux/amd64` only
- Visibility: public, anonymous pull, no `:latest` tag published

See [Container Deployment](../security-server/container/deployment.md) for deployment steps.

## 4. CamDX adaptations

- CamDX branding across all package tracks and the container image.
- Cambodia/CamDX PKI adaptations (CamDX-specific PKI classes).
- CamDX package naming conventions (`camdx-*` package names, versions matching §2).

## 5. Scope boundaries

The following are separate from this release and are not covered by it:

- **High Availability.** Existing CamDX HA deployments remain supported. For a new HA deployment, an upgrade of an existing HA deployment, or a topology change, coordinate with CamDX before implementation; see [Ubuntu HA](../security-server/ubuntu/high-availability-installation.md) and [RHEL HA](../security-server/rhel/high-availability-installation.md).
- **Member migration.** CamDX's approved member Security Server migration procedure is Parallel Replacement / Blue-Green: `APPROVED - FINAL`; see [Upgrade and Migration](../security-server/upgrade/README.md) and [Parallel Replacement](../security-server/upgrade/parallel-replacement.md). Approval of the procedure does not by itself authorize any member's production migration: execution against a real member requires explicit CamDX coordination and authorization for that migration. Production member rollout is not generally authorized; migration proceeds only within a CamDX-coordinated wave.
- **Central Server migration.** A separate CamDX-side track, unrelated to member action and not authorized for production by this release.
- **HTTPS compatibility validation.** Remains open.
- **CamDX Meter / end-to-end Operational Monitoring ingestion.** Remains open. Local and remote Operational Monitoring are supported deployment topologies (see [Network Requirements](../security-server/network-requirements.md)); end-to-end CamDX Meter ingestion is a separate, not-yet-closed item.
- **Overall production rollout.** Not closed. Package and container availability do not by themselves mean the platform is ready for production-wide use; every item above must close first.

## 6. What this release does not authorize

This release does not authorize whole-estate production migration, does not close any item in §5, and does not permit a member to perform an in-place upgrade of an existing Security Server using the fresh-installation guides; see [Upgrade and Migration](../security-server/upgrade/README.md) for the approved migration path.
